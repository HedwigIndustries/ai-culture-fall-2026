# Сравнение исходного и подготовленного набора

Таблица — `data/processed/before_after.csv`. Метрики считаются одинаково для обоих наборов.

| Метрика | Исходный | Подготовленный |
|---|---|---|
| строк | 5 248 | 4 981 |
| столбцов | 21 | 12 |
| пропуски в diff, файле, типе | 20 | 0 |
| дубли | 31 | 0 |
| diff больше 1 000 токенов | 206 | 0 |
| замечание больше 1 000 символов | 21 | 0 |
| строк с CRLF | 1 021 | 0 |
| @упоминания | 133 | 0 |

| метка `security` | 62 | 44 |

Распределение severity в подготовленном наборе: minor 2 180, none 1 725, question 661, blocker 202, nit 143, major 70.

## Что изменилось

- Ушли 267 строк (5,1 %): дубли, пустые diff и всё, что больше лимита входа.
- Осталось 12 колонок из 21: без ников, кода до и после правки и метаданных PR.
- Добавлены `severity` и коды категорий, `diff_tokens`, флаги переразметки.
- Метка `security`: 62 → 44 — у 10 замечаний про именование и опечатки она заменена на `suggestion`, ещё 8 строк с этой меткой ушли при очистке (дубли и большие diff).

## Почему итоговый набор лучше подходит для задачи

1. **Каждая строка — честный кейс для агента.** Нет дублей, которые удвоили бы вес отдельных PR, и пустых diff, на которых агенту нечего проверять.
2. **Вход агента ограничен.** Diff не больше 1 000 токенов (медиана 209 после очистки против 223 в исходном наборе), так что стоимость одного вызова модели предсказуема, а eval не зависит от редких огромных фрагментов.
3. **Разметка в шкале агента.** `severity` совпадает с тем, что выдаёт агент, поэтому recall и ложные тревоги считаются без перекодирования. Шумная метка `security` больше не занижает recall по безопасности.
4. **Нет персональных данных.** Ники удалены из колонок и из текста замечаний, набор можно хранить и передавать.
5. **Только нужное.** 12 колонок вместо 21: агенту нужен `diff_context`, оценке — `comment_text`, `comment_type` и `severity`.
