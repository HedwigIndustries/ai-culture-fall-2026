# LLM-слой

## Провайдеры

| `--llm` | Клиент | Когда |
|---|---|---|
| `none` | — | по умолчанию; только правила |
| `openai` | `OpenAICompatClient` | любой OpenAI-совместимый API; в прототипе OpenRouter `qwen/qwen3.5-plus-20260420` |
| `gigachat` | `GigaChatClient` | целевой вариант для банка (данные в РФ) |

В проде код банка не уходит за периметр: GigaChat или on-prem Qwen через `openai`-клиент. OpenRouter — только для прототипа на открытых и синтетических данных.

## Вызов

- Один запрос на `.py`-файл с добавленными строками: `SYSTEM_PROMPT` + заголовок MR + замаскированный diff + список найденного правилами (`ALREADY_FOUND`).
- `temperature = 0.1`; `OPENAI_REASONING=off` отключает рассуждения модели: ~500 выходных токенов вместо ~6 000, 7 с вместо 49 на демо-MR.
- Ответ — строгий JSON `{"findings": [{line, severity, category, message, suggestion, confidence}]}`; `parse_findings` достаёт первый JSON-объект.

## Валидация (`agent._validate`)

Отбрасываем: строку вне добавленных, `bool` вместо `int`, severity вне шкалы, пустой текст, замечание на строке, уже отмеченной правилом. Нечисловая `confidence` → 0,5. Всё отброшенное — в `dropped_by_validation`.

## Факты из прогона (Qwen 3.5 Plus, `OPENAI_REASONING=off`)

Eval, 120 кейсов: 118 вызовов LLM, в среднем 747 входных и 171 выходной токен на вызов, ~3 с. На коде без замечаний LLM пишет замечания в 65 % случаев — поэтому человек в контуре обязателен. Цифры — `agent/eval/results/eval_openai.json`, разбор — `docs/agent/quality.md`.

## Стоимость

Агент стоимость не считает: в черновике, ответе API и результатах eval есть только токены. Стоимость считается по токенам и тарифу модели отдельно (экономика проекта).
