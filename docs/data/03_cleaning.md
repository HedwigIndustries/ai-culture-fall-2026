# Очистка и преобразование данных

Цифры — из `notebooks/data_preparation.ipynb`. Вход — `data/raw/github_codereview_python.csv` (5 248 строк, 21 колонка).

## Найденные проблемы

Доля — от всех 5 248 строк (поэтому, например, длинных замечаний 0,4 %, а не 0,6 % от строк с замечанием).

| Категория | Проблема | Строк | Доля |
|---|---|---|---|
| пропуски | пропуск `reviewer_username` (у кода без замечаний — ожидаемо) | 1 726 | 32,9 % |
| пропуски | пропуск `diff_context` | 20 | 0,4 % |
| пропуски | пропуск `after_code` | 1 | 0,02 % |
| дубликаты | дубли (repo, PR, файл, замечание) после нормализации | 31 | 0,6 % |
| выбросы | diff больше 1 000 токенов | 206 | 3,9 % |
| выбросы | замечание больше 1 000 символов | 21 | 0,4 % |
| ошибки форматов | CRLF в diff или замечании | 1 021 | 19,5 % |
| ПДн | @упоминания в замечаниях | 133 | 2,5 % |
| ПДн | `/home/<ник>` в замечаниях | 2 | 0,04 % |
| секреты | ключ AWS в коде open-source проекта (замаскирован уже при загрузке, `data/fetch_raw.py`) | 4 | 0,08 % |
| некорректные значения | `security` с текстом без security-лексики | 12 | — |
| некорректные значения | `security` без текста, только блок suggestion | 5 | — |

## Что сделано и почему

| Шаг | Строк после | Удалено | Почему |
|---|---|---|---|
| исходно | 5 248 | — | |
| нормализация текста: CRLF → LF, пробелы в конце строк, strip | 5 248 | 0 | разные переводы строк и хвостовые пробелы мешают находить дубли |
| удаление дублей (repo, PR, файл, замечание) | 5 217 | 31 | одно и то же замечание, снятое на разных версиях diff, — двойной вес в оценке |
| удаление строк с пустым diff | 5 197 | 20 | агенту нечего анализировать |
| удаление diff больше 1 000 токенов | 5 001 | 196 | из 206 таких строк 10 ушли раньше вместе с дублями; лимит входа агента: ~96-й перцентиль, стоимость вызова предсказуема; обрезать diff нельзя — агент увидит код без конца функции |
| удаление замечаний больше 1 000 символов | 4 981 | 20 | из 21 такой строки одна ушла на прошлых шагах; это обсуждения, а не замечания |

Без удаления строк:

- **`@ник` → `@user`, `/home/<ник>` → `/home/user`** в тексте замечаний. Текст остаётся эталоном для оценки, а ники убираются. Декораторы вида `@pytest`, `@property` не трогаются.
- **Переразметка `security`.** 10 замечаний с текстом, но без security-лексики (например, «Can we call this `CONTROL_ESCAPE`», «Typo in comment») → `suggestion`, флаг `label_fixed`. Ещё 2 таких строки ушли вместе с дублями и большими diff. 5 замечаний без текста (только блок кода) оставлены `security` с флагом `label_unverified`: по ключевым словам их не проверить. Иначе опечатка с меткой `security` засчитывалась бы агенту как промах по безопасности.
- **Удалены 17 колонок**, включая ники авторов и ревьюеров (ПДн), код до и после правки, метаданные PR и репозитория. Агенту и оценке они не нужны; удалить надёжнее, чем хешировать. `reviewer_comment` переименован в `comment_text`; у кода без замечаний текст пустой вместо `No issues found.`.

## Преобразования

| Поле | Как получено | Зачем |
|---|---|---|
| `review_id` (int) | номер строки в исходном файле | связь с исходными данными |
| `diff_tokens` (int) | длина diff / 3,5 | лимит входа и расчёт стоимости |
| `severity` | bug, security → blocker; performance → major; refactor, suggestion → minor; style, nitpick → nit; question → question; none → none | та же шкала, что у агента: выход сравнивается с разметкой без перекодирования |
| `severity_id` (int) | порядковое кодирование: none 0, question 1, nit 2, minor 3, major 4, blocker 5 | у severity есть порядок |
| `comment_type_id` (int) | Label Encoding по алфавиту: bug 0, nitpick 1, none 2, performance 3, question 4, refactor 5, security 6, style 7, suggestion 8 | у типа порядка нет, код нужен для компактного хранения и группировки |
| `label_fixed`, `label_unverified` (bool) | флаги переразметки `security` | видно, какие метки менялись |

Масштабирование и one-hot не делали: модель не обучается, числовых признаков для неё нет.

## Eval-набор

`data/processed/eval.csv` — по 20 случайных строк (seed 42) на каждый severity, всего 120. Берутся строки с diff не короче 40 токенов: более короткий diff — одна-две строки без контекста. Самый редкий класс после очистки — major, 70 строк, так что 20 набирается везде.
