# Качество агента: известные проблемы и что делать дальше

Цифры — `agent/eval/results/eval_openai.json`, `eval_none.json`: 120 кейсов `data/processed/eval.csv`, по 20 на каждый severity, модель `qwen/qwen3.5-plus-20260420` через OpenRouter.

## Метрики MVP

| | recall | recall по blocker | ложные тревоги |
|---|---|---|---|
| правила | 18 % | 25 % | 25 % |
| LLM | 69 % | 55 % | 65 % |
| вместе | 77 % | 70 % | 75 % |

Числа — из сохранённого прогона (`agent/eval/results/eval_openai.json`); повторный прогон давал близкие значения с разбросом в несколько процентных пунктов. LLM вызывалась на 118 кейсах (в двух diff нет добавленных строк). В среднем 747 входных и 171 выходной токен на вызов, 3,2 с, ошибок и пропусков нет.

## Известные проблемы

1. **Качество ревью сильно зависит от модели.** В MVP — небольшая недорогая `qwen/qwen3.5-plus-20260420` с выключенными рассуждениями (`OPENAI_REASONING=off`): выбрана ради скорости (~3 с) и цены, а не качества. Цифры ниже — оценка этой модели, а не потолок подхода: агент написан так, что модель меняется переменными окружения без правки кода.
2. **LLM почти не отличает код с замечанием от чистого.** Пишет что-то в 69 % кейсов с замечанием человека и в 65 % на чистом коде.
3. **Severity LLM не совпадает с разметкой.** major/blocker ставит на чистом коде в 40 % кейсов, на настоящих блокерах — в 30 %.
4. **Правила на этом наборе ловят в основном стиль.** Секретов, SQL-инъекций и ПДн в open-source почти нет, поэтому SEC-правила здесь не проверены; их проверяют тесты и демо-MR.
5. **Результат LLM плавает между прогонами** на 10–15 п. п. при 20 кейсах в классе (temperature 0.1).
6. **Метрика грубая.** Засчитывается любое замечание, а не совпадение по смыслу с замечанием человека: recall завышен. «Чистый код» — это только то, что ревьюер open-source промолчал: часть ложных тревог может быть верными замечаниями.
7. **Правила построчные.** Многострочные конструкции (SQL в переменной, вызов на нескольких строках), пустые строки между функциями и порядок импортов не видны.

## Что делать дальше

По возрастанию усилий:

1. **Разобрать вручную 15–20 ложных тревог** — шум модели или пропуск человека. Даст реальную долю ложных тревог.
2. **Ужесточить LLM:** промпт «пиши только то, что сломает работу», порог `confidence` ≥ 0,8, LLM — только major и blocker, мелочи — правилам. Повторить eval.
3. **Точнее мерить:** LLM-судья сравнивает замечание агента с замечанием человека по смыслу; больше кейсов на класс; несколько прогонов и среднее.
4. **Банковский eval:** 150–200 размеченных MR команды на пилоте — проверка SEC-правил и LLM на своём коде.
5. **Модель:** прогнать тот же eval на более сильных моделях (крупнее, с включёнными рассуждениями), на GigaChat и on-prem моделях; выбрать по соотношению качества, времени и токенов.
6. **Продукт (вне MVP):** авторизация к сервису, вебхук из MR, предложения правок кода.
