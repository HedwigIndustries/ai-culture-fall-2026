## ADDED Requirements

### Requirement: Загрузка набора
`data/fetch_raw.py` SHALL скачивать набор `ronantakizawa/github-codereview` с Hugging Face и сохранять только строки с `language = Python` в `data/raw/github_codereview_python.csv`. Если файл уже есть, скрипт SHALL его не перезаписывать.

#### Scenario: Первый запуск
- **WHEN** файла нет и выполнен `uv run python data/fetch_raw.py`
- **THEN** создан `data/raw/github_codereview_python.csv`: 5 248 строк, 21 колонка, только `language = Python`

#### Scenario: Повторный запуск
- **WHEN** файл уже есть
- **THEN** файл не меняется

### Requirement: Описание набора
Ноутбук `notebooks/data_analysis.ipynb` SHALL читать `data/raw/github_codereview_python.csv` и выводить число строк, репозиториев и PR, распределение строк по репозиториям, типы и пропуски полей, описательную статистику числовых полей и долю примеров с замечанием и без.

#### Scenario: Описание
- **WHEN** ноутбук выполнен
- **THEN** выведены число строк, репозиториев и PR, таблица «поле → тип, пропуски», описательная статистика и доля примеров без замечаний

### Requirement: Анализ замечаний
Ноутбук SHALL выводить распределение типов замечаний (`comment_type`) и долю тем в тексте замечаний по фиксированному списку ключевых слов (тесты, обработка ошибок, безопасность, именование, производительность) и сохранять графики в `docs/data/fig/analysis_*.png`.

#### Scenario: Типы замечаний
- **WHEN** ноутбук выполнен
- **THEN** выведены доли типов и тем, графики лежат в `docs/data/fig/analysis_*.png`

### Requirement: Размер полей
Ноутбук SHALL выводить распределение размеров `diff_context` (символы, строки, оценка токенов как символы / 3,5) и текста замечания (символы): перцентили p50, p90, p95, p99, максимум, гистограмму и долю строк сверх порогов 500, 1 000, 2 000 токенов для diff и 500, 1 000 символов для замечаний.

#### Scenario: Основа для лимита входа
- **WHEN** ноутбук выполнен
- **THEN** выведена таблица перцентилей и доля строк, которые отсечёт каждый порог

### Requirement: Выводы
Ноутбук SHALL завершать анализ выводами: какие замечания преобладают, сколько кода проходит ревью без замечаний, какой лимит размера diff и замечания разумен для агента, ограничения набора и достаточно ли данных для оценки агента.

#### Scenario: Выводы в ноутбуке
- **WHEN** ноутбук выполнен
- **THEN** последняя ячейка называет преобладающие типы замечаний, долю кода без замечаний, рекомендуемый лимит, ограничения набора и отвечает, достаточно ли данных для оценки агента
