# Design

## Context

Вход — `data/raw/github_codereview_python.csv`: 5 248 строк, 21 колонка. Проблемы: дубли (часть отличается только CRLF и пробелами в конце строк), пустые diff, diff до ~3 700 токенов и замечания до 3 778 символов, ники авторов и ревьюеров, метка `security` на опечатках и переименованиях.

## Goals / Non-Goals

**Goals:**
- Каждая строка — уникальный кейс с непустым diff, который агент может принять.
- Только поля, нужные агенту и оценке; без персональных данных.
- Разметка в той же шкале severity, что и выход агента.
- Eval-набор, сбалансированный по severity, с кодом без замечаний.

**Non-Goals:**
- Ручная переразметка всех категорий.
- Загрузка и описательный анализ набора.

## Decisions

- **Лимит: diff до 1 000 токенов, замечание до 1 000 символов; строки сверх лимита удаляются.** 1 000 токенов — около 96-го перцентиля diff (медиана 223): отсекается ~4 % строк, а стоимость вызова остаётся предсказуемой. Альтернатива — обрезать diff: агент получил бы код без конца функции и писал бы ложные замечания.
- **Лишние поля удаляются, а не обезличиваются.** Ники, код до и после правки, метаданные PR и репозитория агенту и оценке не нужны. Альтернатива — хешировать ники: остаётся поле, которое никто не читает. Ключ дублей (repo, PR, файл, замечание) считается до удаления.
- **Перед поиском дублей текст нормализуется: CRLF → LF, без пробелов в конце строк, strip.** Без этого не находятся 4 дубля из 31. Альтернатива — схлопывать все пробелы: меняет код в блоках suggestion.
- **В тексте замечаний `@ник` → `@user`, `/home/<ник>` → `/home/user`.** Текст замечания остаётся: это эталон для оценки. Альтернатива — удалить такие замечания: теряется около 150 строк.
- **Переразметка `security` по лексике.** Замечание с текстом, но без security-лексики → `suggestion` с флагом `label_fixed`. Если текста нет (только блок suggestion) — метка остаётся, флаг `label_unverified`. Без этого опечатка с меткой `security` считалась бы промахом агента и занижала бы recall. Альтернатива — переразметить вручную все 62 строки: для MVP дорого.
- **Категории: `severity` — порядковое кодирование, `comment_type` — Label Encoding.** У `severity` есть порядок, и шкала совпадает со шкалой агента; у `comment_type` порядка нет. Альтернатива — one-hot: нужен только для обучения модели, а её нет.
- **Без масштабирования.** Числовых признаков для модели нет; `diff_tokens` нужен как есть — для лимита и расчёта стоимости. Альтернатива — min-max: значения станут непонятны без обратного преобразования.
- **Eval — по 20 примеров на каждый severity (120 кейсов), diff не короче 40 токенов.** Самый редкий класс, `major`, — 71 строка после очистки. Diff короче 40 токенов — одна-две строки без контекста. Альтернатива — весь набор: дольше и дороже, а метрики для MVP те же.

## Risks / Trade-offs

- Удалены diff больше 1 000 токенов → на больших изменениях агент на этом наборе не проверяется.
- Переразметка `security` по ключевым словам → строка со словом из списка, но без проблемы безопасности, остаётся `security`.
- Ники внутри кода `diff_context` (копирайты, пути) не удаляются → в наборе остаются публичные ники из OSS; правка кода исказила бы eval.
- В eval около 4 security-кейсов из 20 blocker → recall по безопасности почти не измеряется.
