# Design

## Context

Вход — набор `ronantakizawa/github-codereview` на Hugging Face; после фильтра по Python — 5 248 строк, 21 колонка. В строке есть diff, текст замечания и его категория; часть строк — код, прошедший ревью без замечаний.

## Goals / Non-Goals

**Goals:**
- Воспроизводимо получить набор реальных ревью Python-кода.
- Понять, какие замечания преобладают, чтобы задать приоритеты агента.
- Выбрать лимит размера diff и замечания для входа агента.

**Non-Goals:**
- Обучение модели: модель не обучаем, набор нужен для анализа и оценки агента.
- Очистка и преобразование данных.

## Decisions

- **Набор — `ronantakizawa/github-codereview`, только Python.** Замечания пишут люди, ботов нет, лицензии репозиториев permissive. Альтернатива — собирать ревью через GitHub API: нужен токен, и неизвестно, сколько данных наберётся. Русскоязычные бенчмарки ревью не подходят: в них мало Python и скрыт текст замечаний.
- **Хранение в CSV.** Открывается в Excel, Python для этого не нужен. Альтернатива — Parquet: компактнее, но без Python не открыть.
- **Токены — оценка «символы / 3,5».** Для выбора лимита хватает грубой оценки. Альтернатива — токенизатор модели: лишняя зависимость, и модель для этого ещё не выбрана.
- **Темы замечаний — по ключевым словам.** Просто и воспроизводимо. Альтернатива — классификация через LLM: стоит денег и даёт разный результат от прогона к прогону.
- **Ноутбук `data_analysis.ipynb` — сам исходник.** Правится в Jupyter и прогоняется через `nbconvert --execute`. Выводы ячеек хранятся в `.ipynb`, и GitHub показывает их без запуска. Альтернатива — генерировать ноутбук скриптом: лишний слой, который тоже надо поддерживать.

## Risks / Trade-offs

- Код из open-source, а не банковский → банковских дефектов (ПДн, секреты в банковском коде) в данных почти нет, и на этом наборе их не проверить.
- Часть `comment_type` размечена эвристикой → доли типов приблизительные.
- Половина строк из 15 репозиториев → доли типов и тем смещены к привычкам этих проектов.
