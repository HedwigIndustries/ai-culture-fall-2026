# Стандарты разработки

## Правила для AI-агента (Claude Code)

- Работа по SDD: сначала спека в `openspec/changes/<id>/`, потом код; порядок чтения — в `openspec/config.yaml`.
- Делать только задачи из `tasks.md`; неясно или противоречит спеке — спросить, не додумывать.
- Простота важнее общности: без новых сервисов, слоёв и зависимостей, если их не требует спека.
- Не ослаблять ограничения из [security.md](security.md): нет approve/merge и публикации без человека, секреты только в `agent/.env`, в LLM — только замаскированный текст.
- Цифры в отчёте и спеках — из выводов ноутбуков, `data/processed/*.csv`, `agent/eval/results/*.json`, не из памяти.
- После выполнения задачи — отметить её в `tasks.md`; проверки — по [testing.md](testing.md).

## Python

- Python 3.11, `from __future__ import annotations`, типы в сигнатурах.
- Зависимости только через `pyproject.toml` + `uv.lock`; агенту — минимум (`requests`, `fastapi`, `pydantic`, `uvicorn`).
- Внешние HTTP-вызовы — всегда с `timeout`.
- Ошибки внешних сервисов не роняют ревью: ловим конкретные исключения, пишем в результат (`llm_errors`), а не `except: pass`.
- Без мёртвого кода и комментариев, пересказывающих код. Комментарий объясняет «почему».
- Ноутбук правится в Jupyter; перед коммитом — прогнать целиком, чтобы выводы ячеек были актуальны.

## Правила агента

- Новое правило: `Rule` в `rules.py` с id `SECnnn` / `BUGnnn` / `STYnnn`, severity и рекомендацией + тест на срабатывание и на ложное срабатывание.
- Сообщения правил — по-русски, коротко, как коллега в ревью.

## Тексты (отчёт, спеки, ноутбуки)

- Русский, коротко и конкретно, с цифрами и причинами.
- Без штампов («играет ключевую роль», «важно отметить», «не просто X, а Y»), рекламного тона, лишнего bold и эмодзи.
- Каждая цифра проверяема: ячейка ноутбука, CSV, `agent/eval/results/*.json`.
- Синтетические данные и допущения помечаются явно.

## Спеки OpenSpec

- Требования — `SHALL` / `MUST`, сценарии — `WHEN` / `THEN`, проверяемые тестом или скриптом.
- 2–8 требований на capability; детали реализации — в `design.md`, не в требованиях.
